== Configuration

|===
|`PORT`                   |Listening port (default `3005`).
|`RMU_ATTACK_TABLES_DIR`  |Folder with the tables. Unset or empty: the bundled `tables/` folder.
|===

`RMU_ATTACK_TABLES_DIR` accepts two layouts, checked in this order for every file:

. `<dir>/attack`, `<dir>/critical`, `<dir>/fumble` (the layout of `tables/`).
. `<dir>/attack-tables`, `<dir>/critical-tables`, `<dir>/fumble-tables` (the layout of the workspace `data/core-law` folder, which is not published).

File names are the same in both: `attack/<table>.csv`, `critical/<table>-<severity>.json`, `fumble/<table>.json`, `spellcasting/modifiers.json` and `spell-failure/<realm>.json` (the last two as `spellcasting-tables` and `spell-failure-tables` in the second layout). The spell casting tables are not bundled: `tables/` only has empty templates, so without a data folder those endpoints answer 404. A file missing from the configured folder is read from `tables/`, so a partial folder only overrides the tables it contains. The API logs the folder in use at startup.

In the local Compose stack, `rmu-platform` mounts the workspace `data/core-law` read-only and sets the variable (see its `compose/local-data.yaml`).

== Endpoints

|===
|`GET /v1/attack-tables`                                |Gets the ids of the attack tables found in the data folder and in `tables/`, sorted.
|`GET /v1/attack-tables/{tableId}/{at}/{roll}`          |Gets the result of an attack roll on the Medium table. `tableId`: lowercase letters, digits and `-` (400 otherwise); `at`: 1-10; `roll`: 1-175, and a roll above the last band of the table reads its top row (the ball tables end at 125).
|`GET /v1/critical-tables/{type}/{severity}/{roll}`     |Gets the result of a critical hit roll. `type`: the letter of the attack tables (`G H I K L O P S T U W`) or `acid`, `holy`, `steam`, `subdual`; `severity`: `A`-`E`, or `Z` (Section 9.8); optional `?location=`. 400 for an invalid type or severity, 404 for a missing table.
|`GET /v1/fumble-tables`                                |Gets the ids of the fumble tables found in the data folder and in `tables/`, sorted.
|`GET /v1/fumble-tables/{type}/{roll}`                  |Gets the result of a fumble roll on a specific table (400 for an invalid id, 404 for a missing table).
|`GET /v1/spellcasting-tables/modifiers`               |Gets the spell casting modifiers (Spell Law table 4-2).
|`GET /v1/spell-failure-tables/{realm}/{type}/{roll}`   |Gets a spell failure result (Spell Law tables 4-4). `realm`: `channeling`, `essence` or `mentalism`; `type`: `elemental`, `force`, `informational` or `utility`; `roll`: the modified open-ended roll (below 1 reads the first row).
|===

`tables/` bundles every Core Law table: the 39 Medium attack tables (workspace spec 033), the 15 critical tables with severities A-E (75 files, with the `injury` field of workspace spec 013) and the 10 fumble columns (spec 034). Effects only come from the printed symbols; `staggered` always carries `rounds` and `value` (AP lost).

Only the Medium attack tables are served (workspace spec 033). The book's Small and Big tables are the Medium one with the critical severity one step down or up (down to `Z`) and the hits ×0.75 or ×1.5 rounded half up, so the caller (`rmu-api-tactical`) applies the attack size. `tables/attack` bundles the 39 Medium tables of Core Law.

The response format for attack rolls is:

[source,json]
----
{
    "text": "16DP",
    "damage": 16,
    "criticalType": "P",
    "criticalSeverity": "D"
}
----

The response format for critical hit rolls is:

[source,json]
----
{
    "rollMin": 67,
    "rollMax": 75,
    "dmg": 17,
    "effects": [
        {
            "status": "bleeding",
            "value": 2
        },
        {
            "status": "penalty",
            "value": -5
        }
    ],
    "location": "leg",
    "message": "Lower leg wound bleeds freely."
}
----

Critical entries may carry an optional `injury` classification, returned as is:

[source,json]
----
"injury": { "type": "bone", "secondary": ["muscle-tendon"], "flags": ["permanent-risk"] }
----

`type` and `secondary` take `bone`, `cut-burn`, `muscle-tendon`, `organ`, `poison-disease`, `skin-tissue` or `unknown`; `flags` takes `permanent-risk`, `limb-loss`, `blinding` or `paralysis`. The bundled tables do not include it; when it is missing, clients infer the type from the critical table (workspace spec 013).

A spell failure result carries the text for the spell type and the power points it suggests (`pp`: `none`, `one`, `half-down`, `half-up`, `normal`, `double`, `triple` or `all`); the caller confirms them:

[source,json]
----
{ "realm": "essence", "type": "force", "roll": 42, "rollMin": 41, "rollMax": 60, "text": "...", "pp": "normal" }
----

The response format for fumble rolls is:

[source,json]
----
{
    "rollMin": 51,
    "rollMax": 60,
    "effects": [
        {
            "status": "stunned",
            "rounds": 2,
            "value": -25
        }
    ],
    "text": "You try to impress your opponent with a spin maneuver. Too bad. Spend two rounds Stunned."
}
----
